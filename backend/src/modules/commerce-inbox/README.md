# Marketplace conversation inbox

The `/v1/commerce-inbox` HTTP module is a business interface over `CommerceService`; it has no new ledger, marketplace client or token access. Reads, replies and explicit mark-read commands go through the existing operation/outbox worker, idempotency key and current tenant, role, store, connection, marketplace scope and read-only checks. Marketplace messages remain the source of truth. Request payload/results expire under the commerce retention policy; they are not copied into exports, audits or logs.

The reviewed Indonesia seller contracts are TikTok Shop Create Conversation, Get Conversations/Get Conversation Messages (202309), Send Message (202606), Upload Image for Buyer Messages and Mark Buyer Messages as Read. System locale is `id-ID`, message page size is ten. Cursor pagination is opaque. Read requests never implicitly mark messages read. A successful send means marketplace acceptance; delivery must be checked by reading marketplace messages. Unknown outcomes never cause an automatic resend.

The receipt projection excludes invisible messages, raw structured JSON, private participant fields and arbitrary provider diagnostics. Text is bounded and rendered as text. Buyer nicknames are shown only to authorized inbox users. Images are uploaded through the existing private commerce file route, then sent using a successful upload receipt belonging to the same user and store; the caller cannot provide an arbitrary image URL. Video uploads use the reviewed fixed chat target, support small single-chunk files through 100 MiB, and bind the returned resource ID to `content.vid`; creator upload receipts cannot be reused for chat. All eight documented send types (text, image, video and product/order/refund/coupon/logistics cards) use typed forms and exact string IDs. Uploads expire and never traverse the API process to the marketplace.

Shopee chat is not inferred from seller or AMS credentials. For a new ISV integrator, Shopee announcement 1026 closes new Customer Service App and Chat OpenAPI applications from 18 November 2024; FAQ 716 repeats ISV unavailability. API keys and the FAQ message-quota whitelist do not grant new Chat eligibility. Existing apps must be checked individually; neither blanket legacy revocation nor continued access is assumed. Current request/response docs require login/permission. See docs/audits/shopee-chat-policy-evidence.json for official URLs, quotes and retrieval hashes. This module does not claim assignment/CRM state, push delivery, omnichannel WhatsApp, Shopee chat, AI auto replies, or marketplace application approval. Real account testing still requires Customer Service app access and an authorized Indonesia shop.

Tests cover invisible message exclusion, bounded safe projection, exact string IDs, documented text serialization, and invalid/cross-store/upload-receipt attachment rejection.
